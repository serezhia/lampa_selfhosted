# План перехода на VOD-плейлисты для транскодирования (On-the-Fly HLS)

## Суть проблемы текущего подхода
Сейчас используется **Live HLS** плейлист. При перемотке на небуферизованный участок фронтенд-плагин убивает старый поток, запрашивает новый UUID, подменяет источник в плеере и пытается обмануть UI Лампы с помощью "виртуального таймлайна" (подмена `video.currentTime` и `video.duration`). Это приводит к конфликтам с внутренними механизмами Лампы:
- Ошибки `Cannot redefine property: enabled` при пересоздании `hls.js`.
- Плеер отматывает время назад из-за внутренних сохранений прогресса.
- Зависание надписи "Перемотка...".
- Спам 404 ошибками в сети.

## Новое решение: VOD HLS (Индустриальный стандарт)
Мы переходим на подход, который используют Plex и Jellyfin. Бэкенд сразу генерирует **полный статический плейлист** (VOD) на всю длину фильма. Фронтенд вообще не знает о том, что видео транскодируется на лету. Вся магия перемотки происходит на бэкенде.

### Шаг 1: Бэкенд — Генерация статического плейлиста
1. При запросе `/api/transcoding/start` бэкенд делает `ffprobe` и получает точную длительность видео (например, 7200 секунд).
2. Задается фиксированная длина сегмента (например, 10 секунд).
3. Бэкенд высчитывает количество сегментов (720) и моментально генерирует файл `playlist.m3u8`, содержащий список всех сегментов от `segment_00000.ts` до `segment_00719.ts`, завершая его тегом `#EXT-X-ENDLIST`.
4. Бэкенд возвращает фронтенду URL этого плейлиста. UUID остается **один** на весь сеанс.

### Шаг 2: Бэкенд — Умная отдача сегментов (On-the-Fly)
1. Плеер запрашивает `segment_00000.ts`. Бэкенд запускает `ffmpeg` с начала и отдает файл, как только он появляется.
2. Пользователь перематывает на середину. Плеер сам высчитывает нужный сегмент (например, `segment_00360.ts`) и запрашивает его.
3. Роут отдачи `.ts` файлов (`[streamId]/[filename].dart`) проверяет наличие файла:
   - Если файл есть — просто отдает его.
   - Если файла нет (пользователь перемотал вперед), бэкенд:
     1. Убивает текущий процесс `ffmpeg`.
     2. Высчитывает время старта: `360 * 10 = 3600 секунд`.
     3. Запускает новый `ffmpeg` с параметрами `-ss 3600` и `-start_number 360`.
     4. Дожидается появления `segment_00360.ts` на диске и отдает его плееру.

### Шаг 3: Фронтенд — Тотальная чистка
1. Удалить `injectVirtualTimeline` и все манипуляции с `Object.defineProperty`.
2. Удалить перехват перемотки (`seekTimeout`, проверки `buffered`/`seekable`).
3. Удалить логику ручного уничтожения и пересоздания `hls.js`.
4. Плагин должен стать максимально простым: получить URL плейлиста от бэкенда и передать его в `Lampa.Player.play(playback)`.

## Возможные проблемы и пути их решения

1. **Рассинхрон длины сегментов:**
   - *Проблема:* `ffmpeg` режет сегменты по ключевым кадрам (keyframes). Если мы скажем резать по 10 секунд, реальный сегмент может получиться 9.5 или 10.5 секунд. Из-за этого статический плейлист (где мы жестко пропишем `#EXTINF:10.0`) будет немного врать, что может вызвать подергивания при перемотке.
   - *Решение:* Использовать флаги `ffmpeg` для принудительной вставки ключевых кадров (`-force_key_frames "expr:gte(t,n_forced*10)"`) или смириться с небольшой погрешностью (обычно `hls.js` умеет это корректировать на лету).

2. **Таймауты при перемотке:**
   - *Проблема:* Запуск нового `ffmpeg` с `-ss` занимает время (особенно на тяжелых торрентах). Браузер может отвалиться по таймауту, не дождавшись `.ts` файла.
   - *Решение:* Убедиться, что `-ss` стоит **до** `-i` (Fast Seek). Настроить таймауты в `hls.js` на фронтенде (через параметры Lampa, если возможно), чтобы он ждал сегмент подольше.

3. **Очистка старых сегментов:**
   - *Проблема:* Если пользователь прыгает по всему фильму, папка с транскодом быстро забьет диск.
   - *Решение:* Бэкенд должен периодически удалять старые `.ts` файлы, которые находятся далеко от текущего читаемого сегмента (например, хранить только окно в 50 сегментов вокруг текущего).

4. **Субтитры:**
   - *Проблема:* Извлечение субтитров (`.vtt`) сейчас идет параллельно. При перемотке субтитры могут не успеть извлечься для новой позиции.
   - *Решение:* Оставить извлечение субтитров как есть (оно извлекает весь файл целиком). Так как UUID теперь один, субтитры извлекутся один раз в фоне и будут доступны для всего фильма.
